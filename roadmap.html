Acceptance criteria

The nine checklists the finished product is measured against. These are the definition of done for the whole system, not for any single phase.

30.1

Core GEO End-to-End

  1. User authenticates.
  2. User creates workspace.
  3. User creates brand/domain.
  4. User chooses market/platform.
  5. User creates prompt.
  6. Scheduler creates PromptRun.
  7. Provider adapter executes.
  8. AIAnswer persists.
  9. Brand mention extraction completes.
  10. Competitors are detected.
  11. Rank is calculated.
  12. Sentiment is calculated.
  13. Citations are normalized.
  14. Metrics aggregate.
  15. Overview displays real data.
  16. Prompt Detail displays real data.
  17. Chat Preview opens original evidence.
  18. Source Detail shows citations.
  19. Data persists across sessions.
  20. Cross-workspace access is rejected.
30.2

Readiness Scan End-to-End

  1. User selects a brand domain.
  2. User starts scan.
  3. API returns job immediately.
  4. Target kind is detected.
  5. Applicable methodology version is attached.
  6. Applicable checks run.
  7. N/A checks are excluded correctly.
  8. Evidence is persisted.
  9. Layer scores calculate.
  10. Overall score calculates.
  11. Grade calculates.
  12. Failed checks have recommendations.
  13. Scan UI updates through progress events.
  14. User can reopen the completed scan.
  15. User can rerun selected checks.
  16. Targeted re-check returns fresh evidence.
  17. Historical full scan remains immutable.
  18. Methodology version is visible.
  19. Score differences can be attributed to scan/site/methodology changes.
  20. SSRF protections prevent private-network scanning.
30.3

Agent Journey End-to-End

  1. User selects a curated task.
  2. Journey is queued.
  3. Agent runtime remains scoped to allowed target/action set.
  4. Pages/tools/actions are recorded.
  5. Operational trace is persisted.
  6. Journey can time out safely.
  7. Journey identifies success/failure.
  8. Failure receives taxonomy.
  9. Friction points are generated.
  10. Journey UI displays timeline.
  11. Journey links to recommendations.
  12. No hidden chain-of-thought is exposed/stored as a product dependency.
30.4

Recommendation Quality

  1. What is wrong?
  2. Why does it matter?
  3. What evidence supports it?
  4. What should the user do?
  5. How difficult is it?
  6. What is the expected impact?
  7. How will we verify success?
  8. A recommendation without evidence or verification is not considered complete.
30.5

Multi-Tenancy

  1. For every resource type (Prompt, Answer, Citation, Scan, CheckResult, Journey, Recommendation, Content, Workflow, Integration, Billing record), a user from Workspace A must not be able to read/mutate Workspace B through direct ID.
  2. ...through guessed ID.
  3. ...through changed URL.
  4. ...through changed API payload.
  5. ...through cached response.
30.6

Background Reliability

  1. Every background job is idempotent.
  2. Every background job is retryable where appropriate.
  3. Every background job is observable.
  4. Every background job is correlated to a workspace.
  5. Every background job is correlated to source entity.
  6. Every background job is timeout bounded.
  7. Duplicate job execution must not double-count usage.
  8. Duplicate job execution must not double-create metrics.
  9. Duplicate job execution must not double-send paid actions.
  10. Duplicate job execution must not duplicate recommendations.
30.7

No-Data Semantics

  1. The product distinguishes: not collected, collecting, partial, zero, unknown, not applicable, failed.
  2. These states are not interchangeable.
30.8

Security Acceptance

  1. Auth bypass is tested.
  2. Workspace isolation is tested.
  3. CSRF is tested.
  4. XSS from AI answer is tested.
  5. XSS from crawled HTML is tested.
